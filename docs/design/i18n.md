# i18n

How the UI language works (TE-009). Dutch (`nl`) is the default, English (`en`) the fallback. There is no locale
prefix in URLs (`docs/plan.md` § 7).

## Locale resolution (server)

`App\Http\Middleware\SetLocale` (web group) asks `App\Support\I18n\LocaleResolver` for the locale and sets it for the
request. First match wins:

| Step | Source | Rule |
|---|---|---|
| (M1) | the signed-in user's saved preference | added as the first line of `LocaleResolver::resolve()` |
| 1 | cookie `locale` | exactly `nl` or `en` (the `App\Enums\Locale` allow-list); anything else, including arrays, other casing or path-like values, is ignored and the chain continues |
| 2 | `Accept-Language` | by quality, highest first; the primary subtag counts (`en-GB` = `en`); `q=0`, `*` and unknown languages are skipped |
| 3 | `APP_LOCALE` | `nl` (a value outside the allow-list also gives `nl`) |

- The `locale` cookie is first-party, unencrypted (like `appearance`; it holds no personal data), and is set only by the
  language switch (TE-016), `SameSite=Lax`. Its value is never echoed or logged.
- The response carries `Content-Language: <locale>` and `Vary: Accept-Language`; `<html lang>` is rendered on the
  server (`resources/views/app.blade.php`).
- Unmatched URLs (a 404 outside any route) don't run the web group, so they use the default locale. The localised
  error pages story adds the chain there (e.g. via a fallback route).

## Shared Inertia props (the contract)

Every Inertia response shares, at the top level:

| Prop | Type | Content |
|---|---|---|
| `locale` | `Locale` (`'nl' \| 'en'`, generated from `App\Enums\Locale`) | the resolved locale |
| `fallbackLocale` | `Locale` | `APP_FALLBACK_LOCALE` (`en`) |
| `translations` | `Record<string, string>` | the flat map of `lang/<locale>.json`, **merged over** `lang/<fallback>.json`: a key missing in `nl.json` carries its English text. Only this one map is sent. A key that isn't in it is missing in both files. |

## Lang files

- `lang/nl.json` and `lang/en.json`, the same files for PHP (`__('key')`) and React (`t('key')`).
- Keys are flat strings named `area.thing.action` (lower case, digits, `_`; the dots are part of the key, not nesting).
  Keep the keys sorted and every key in both files (TE-010 checks this in CI).
- Values are **plain text**: no HTML (a Pest test rejects `<` and `>`). Placeholders use Laravel's `:name` syntax.
  Values are escaped when rendered: Blade `{{ __() }}` and React text nodes; never `dangerouslySetInnerHTML`.

## Tests

`tests/Feature/I18n/LocaleResolutionTest.php` (AC1 to AC4, AC9 server side). Fixture lines for tests live in
`tests/Fixtures/lang/*.json` and are merged in per test with `addJsonPath()`, so tests never depend on real UI strings.
Note: Laravel test requests send `Accept-Language: en-us,en;q=0.5` by default; send `Accept-Language: ''` to test the
default locale.

## Using it in React (developer note)

**Add a key.** Add it to both `lang/nl.json` and `lang/en.json`, named `area.thing.action`, keeping the keys sorted.
Placeholders use `:name` (`:Name` and `:NAME` give the capitalised and upper-case forms). Use a literal key in the
call, `t('passkey.added', …)`, never a built one, so the completeness test (`lang-files.test.ts`) can see it.

**Translate.** `const { t } = useTranslation();` from `@/lib/i18n`, then `t('passkey.added', { when: diff })`.
It reads `locale` and `translations` from the shared props, so server and browser render the same text. A missing key
shows the key itself in production and throws in tests. Put `t` in hook dependency lists when needed; it is stable
until the locale changes. Strings that used to sit in a static `Page.layout` (titles, breadcrumbs) go through
`setLayoutProps()` inside the page component, and lists of translated items are built inside the component.

**Format.** `const { formatDate, formatDateTime, formatMoney, formatNumber } = useTranslation();` or the pure
functions from `@/lib/i18n` with the locale as an argument.
- Money is integer cents plus a currency code: `formatMoney(123450, 'EUR')` gives `€ 1.234,50` (nl) or `€1,234.50` (en).
- Always pass the time zone you mean: `formatDateTime(departure, 'Europe/Amsterdam')` for an airport, never the
  runtime's. The default is `Europe/Amsterdam`; times are stored in UTC and the output carries the zone label (`CET`).

**Mark a language change** inside content (an English term in Dutch text) with a `lang` attribute: `<span lang="en">check-in</span>`.
